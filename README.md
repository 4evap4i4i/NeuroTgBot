# NeuroTgBot

Telegram-бот на aiogram: LLM-чат с памятью (Neon Postgres) и поддержкой
вопросов по загруженным PDF-документам через tool-calling.

## Как это работает

1. `/start` — приветствие.
2. Отправь PDF-файл — бот сохранит его в базе и пришлёт ID документа.
3. `/files` — меню с кнопками: список твоих PDF (по названию файла), нажатие
   на кнопку напоминает ID документа для использования в `/say`.
4. `/say <текст>` — обычное сообщение модели. Модель сама решает, как
   получить информацию из PDF: может сразу прочитать документ целиком
   (`read_document`) и запросить конкретные страницы (`get_pages`), либо
   для быстрого случая — получить весь текст документа одним вызовом
   (`get_document`).
5. `/reset` — очистить историю чата.

## Переменные окружения (.env)

- `TOKEN` — токен Telegram-бота
- `NEON` — строка подключения к Postgres (Neon)
- `WEBHOOK` — секретный токен вебхука
- `RENDER_EXTERNAL_URL` — внешний URL деплоя на Render
- `AI_TOKEN` — API-ключ Groq (используется как OpenAI-совместимый эндпоинт)

## Запуск

```
pip install -r requirements.txt
python -m NeuroTgBot
```

## Что доделано (по сравнению с исходным скелетом)

- Хэндлер приёма PDF (`handlers/router_document.py`) — сохраняет файл в Neon.
- `tools/get_document.py` — добавлены `ensure_documents_table` и
  `save_document`, `get_document` теперь ограничен владельцем документа.
- `llm/llm_call.py` — реализован цикл tool-calling: модель может запросить
  `get_document`, результат подставляется, делается повторный запрос за
  финальным ответом.
- `/reset` подключён в `handlers/__init__.py`.
- `/say` без аргумента больше не роняет бота.
- Таблицы `chat_history` и `documents` создаются на старте бота.
- `requirements.txt` дополнен `asyncpg` и `pymupdf`.
- `handlers/router_files.py` — меню `/files` с inline-кнопками по названию
  файла (`filename` из таблицы `documents`), нажатие возвращает ID документа.
  Добавлена `get_user_documents` в `tools/get_document.py`.
- `tools/document_pages.py` — новая пара инструментов для больших PDF без
  забивания контекста лишним: `read_document` отдаёт весь документ целиком
  (постранично, без сокращений) — модель читает его и решает, какие
  страницы нужны; `get_pages` возвращает эти страницы дословно, без единой
  обрезки. При неверном номере страницы ответ начинается с явного
  `⚠️ ОШИБКА`, а не тихой пометкой в конце. К каждому ответу добавлена
  короткая самопроверка для модели (уверена ли она в номерах / та ли это
  информация).
- `llm/llm_call.py` — `call()` переписан на цикл (до `MAX_TOOL_ROUNDS`
  раундов): раньше поддерживался только один раунд tool-calling, чего не
  хватает для цепочки `read_document` → `get_pages`.
- `__main__.py` — `PORT` из окружения теперь приводится к `int`
  (`web.run_app` падал бы на строке).
